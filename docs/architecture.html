Architecture Overview

Factory Inventory Management System

A demo full-stack dashboard for tracking inventory, orders, demand, backlog and spending. It has a Vue 3 single-page app, a read-only FastAPI service, and JSON files loaded into memory at startup. There is no database.

System architecture

Two processes on localhost. The browser talks to the API directly over CORS; Vite does not proxy.

Tech stack

The dependency list is short on purpose, with no UI kit, chart library or state-management library.

Frontend · client/

  • Vue 3 (Composition API) with vue-router 4
  • Vite 8 dev server on port 3000
  • axios for HTTP
  • Charts drawn as custom SVG; layouts in CSS Grid
  • i18n for English and Japanese, with USD/JPY currency switching
  • Global styles live in App.vue

Backend · server/

  • Python 3.11+, FastAPI, Uvicorn on port 8001
  • Pydantic v2 response models
  • Managed with uv (pyproject.toml)
  • No database: JSON files are loaded into memory
  • Data resets on every restart

Testing & tooling

  • pytest + FastAPI TestClient in tests/backend/, about 40 tests
  • No frontend unit tests; browser checks run through Playwright MCP
  • scripts/start.sh and scripts/stop.sh run both servers
  • Claude Code subagents and skills in .claude/

Data flow: a filter change

Example: on the Dashboard, the user picks Warehouse = "San Francisco" and Period = "Q2-2025".

  1. FilterBar updates shared refsuseFilters keeps four module-level refs (period, location, category, status), so every view sees the same selection.
  2. View reacts and refetchesThe view watches the filters, calls getCurrentFilters() and fires its API calls in parallel. Dashboard makes four.
  3. api.js builds the requestIt drops any filter set to "all" and sends the rest as query params, for example /api/orders?warehouse=San%20Francisco&month=Q2-2025.
  1. FastAPI filters in memoryapply_filters runs list comprehensions over the in-memory lists. filter_by_month expands quarters through QUARTER_MAP and substring-matches order_date.
  2. Pydantic shapes the responseThe response_model validates and serializes the result. Summary and spending endpoints return plain dicts.
  3. Vue derives what's displayedRaw responses go into refs such as allOrders and inventoryItems. KPIs, chart series and tables are computed properties.

Known gaps

Worth knowing before you make changes.

Client and server don't fully match
  • api.js defines /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders, but the server doesn't implement them. App.vue calls getTasks and createTask, so those requests return 404.
  • server/main.py defines PurchaseOrder and CreatePurchaseOrderRequest models but no routes use them, and purchase_orders.json is empty.
  • views/Backlog.vue exists but isn't registered in the router in main.js.
  • The API base URL is hardcoded in two places: api.js and Reports.vue.
  • Inventory has no time dimension, so the period filter doesn't apply to it.
